X Spaces Transcriber — build log

Why yt-dlp can't download a passcode-protected Zoom recording.

It isn't a wrong password or an expired link. yt-dlp asks Zoom what to do, Zoom answers “ask the user for a passcode” — and yt-dlp follows the redirect instead of submitting one. The endpoint it would have posted to is gone anyway.

what actually happens

Four calls. The first two succeed, which is what makes this confusing to debug.

01

Load share page

/rec/share/<id>

Page loads fine. The recording exists and hasn't expired.

200 OK
02

Read page data

meetingId: '…' in the page source

The meeting ID parses correctly. So far nothing is wrong.

parsed
03

Ask for the file

/play/share-info/<id>

Zoom replies componentName: "need-password" and a redirect to a passcode page.

passcode required
04

Follows the redirect

/rec/component-page

Lands on an empty SPA shell with no data to read, and gives up.

Unable to extract data
the second dead end

Even patched to submit the passcode, there is nowhere left to send it.

—

Submit the passcode

POST /rec/validate_meet_passwd

The endpoint every script and gist for this posts to.

response

“This API has been deprecated”

{"status": false, "errorCode": 400}

Not rate-limited, not a wrong passcode. Removed server-side — so every tool built on it is broken, not just yt-dlp.

gone for everyone
and

The new page loads a captcha

So reverse-engineering the replacement isn't a path worth building on either.

the takeaway

--video-password is dead code on this path — yt-dlp never reaches the point of using it. That's why the error says “Unable to extract data” rather than “wrong password”, and why hours of retrying passcodes gets you nowhere.
