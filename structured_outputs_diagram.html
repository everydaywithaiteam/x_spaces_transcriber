X Spaces Transcriber — build log

The summary stopped being the source of truth.

Ticker alerts used to be built by running a regular expression over prose Claude had written. That works until Claude formats one bullet differently — and then a ticker disappears from an alerting system without a sound.

v2.1
github.com/everydaywithaiteam/x_spaces_transcriber
before — markdown is the source of truth

Claude writes prose. The pipeline reads that prose back and hopes the shape held.

01

Claude writes markdown

One long document — headings, prose, bullet lists.

02

Regex the bullets

^- \*\*\$([A-Z]{1,6})\*\*

Finds the tickers section, then matches each bullet's exact punctuation.

brittle
03

A bullet renders differently

An en dash instead of an em dash, two tickers on one line, a missing bold marker.

ticker dropped, silently
04

No alert is sent

Nothing errors. Nothing logs. The stock you track was discussed and you never hear about it.

worst failure mode
after — the schema is the source of truth

Claude fills in fields. The markdown you read is rendered from those fields, not parsed back out of them.

01

Claude fills a schema

output_config.format

Typed fields: symbol, stance, context — validated on the way out.

shape guaranteed
02

Read the field

data["tickers"] → symbol

No parsing. The alert reads a list that was never prose to begin with.

03

Render the markdown

Same headings as before, so the email and Notion sync never noticed the change.

a view, not the truth
04

One field = one section

position_intent

Adding “what he's about to buy” was a schema field and a renderer block. No new parsing.

cheap to extend

Tickers found

Malformed symbols

$AMCOR → $AMCR

Amcor's real ticker. Corrected without being asked.

the caveat

A schema guarantees the shape of what comes back. It doesn't guarantee the model won't put strange text inside a field — which is exactly the bug that shipped anyway. Those are different problems.
